Plan de Pruebas: US-002 / Gestión de incorporación de nuevos empleados

Resumen Ejecutivo

Este plan de pruebas define la estrategia integral de aseguramiento de la calidad (QA) para la historia de usuario US-002 orientada al módulo de incorporación de nuevos empleados en la plataforma web de GeekRetail. El alcance contempla pruebas funcionales E2E en navegador web (Chromium/Chrome), análisis de valores límite y partición de equivalencias (ISTQB), verificación de integridad de datos en el DOM, auditoría automatizada de accesibilidad bajo estándares WCAG 2.2 AA (axe-core) y auditoría de calidad técnica (Lighthouse).

Análisis de Riesgos de Prueba

Riesgo General: ALTO

El formulario de registro de empleados impacta directamente los datos de RRHH y nómina. Un análisis estático preliminar de la lógica de cliente reveló defectos de alto impacto:

  • Asignación errónea en salario: El uso de salary = 0 en lugar de una comparación provoca que la validación falle silenciosamente y sobrescribe el valor del salario a 0 al persistir en la tabla visual.
  • Inconsistencias en validación de edad: Discrepancia entre la condición age < 5 || age > 60 y el mensaje comercial '18 a 65 años', permitiendo el registro de infantes y bloqueando a adultos entre 61 y 65 años.
  • Omisión de bloqueo en género: El flag de error se desactiva explícitamente (hasError = false) permitiendo registros sin género.

Recomendaciones Tempranas para Desarrolladores

  • Reemplazar la asignación salary = 0 por una condición lógica estricta parseFloat(salary) <= 0 || isNaN(salary).
  • Sincronizar las reglas de edad con el requerimiento de negocio: cambiar a age < 18 || age > 65.
  • Asegurar que la validación de género asigne hasError = true.
  • Corregir las incongruencias entre mensajes de error y longitudes de Dirección y Teléfono.
  • Ajustar el texto del mensaje de confirmación a: "¡Empleado registrado con éxito!".
