Guía Definitiva de Cucumber

Conceptos clave para el QA Automation Engineer Experimentado

1. Los Cimientos Filosóficos

BDD (Behavior-Driven Development)

Definición: Es una metodología ágil que fomenta la colaboración entre desarrolladores, QA y personas no técnicas o de negocio (Product Owners). BDD no es una herramienta, es la cultura de discutir cómo debe comportarse el sistema antes de programarlo.

Aplicación: Cucumber es la herramienta que materializa BDD permitiendo que esos comportamientos se conviertan en pruebas automatizadas ejecutables.

2. Gherkin: El Lenguaje

Gherkin es el lenguaje estructurado (con palabras clave específicas) que Cucumber entiende. Un archivo `.feature` está escrito en Gherkin.

La Sintaxis de los Pasos (Given, When, Then)
  • Given (Dado): Establece el contexto inicial o precondiciones. (Ej. Estado de la base de datos, usuario logueado).
  • When (Cuando): Describe la acción o el evento principal que el usuario o sistema realiza.
  • Then (Entonces): Describe el resultado esperado o la aserción (assert) que valida si la prueba pasó.
  • And / But (Y / Pero): Se usan para encadenar pasos del mismo tipo y mantener la legibilidad.

3. Conceptos Avanzados de Estructura

Background (Antecedentes)

Definición: Pasos que son comunes a TODOS los escenarios dentro de un archivo Feature. Se ejecutan antes de cada escenario para evitar repetir código.

Feature: Gestión de Carrito

  Background:
    Given que el usuario ha iniciado sesión
    And tiene saldo positivo en su cuenta

  Scenario: Añadir producto
    When añade un libro
    ...
Scenario Outline & Examples (Esquema del Escenario)

Definición: Implementa Data-Driven Testing. Permite ejecutar el mismo escenario exacto múltiples veces utilizando diferentes conjuntos de datos proporcionados en una tabla.

Scenario Outline: Login con múltiples roles
  Given que estoy en el login
  When ingreso el usuario "<usuario>" y clave "<clave>"
  Then debo ver el panel "<panel>"

  Examples:
    | usuario | clave | panel       |
    | admin   | 1234  | Dashboard   |
    | cliente | 5678  | Mi Perfil   |
Data Tables (Tablas de Datos)

Definición: A diferencia de los Examples (que repiten todo el escenario), las Data Tables se usan para pasar listas completas o matrices de datos a un solo paso (step).

Scenario: Crear nuevo usuario con múltiples roles
  Given que el administrador crea el usuario "Juan" con los roles:
    | Rol       | Permiso |
    | Editor    | Leer    |
    | Autor     | Escribir|
  Then el usuario se crea con éxito

4. Organización y Ejecución

Tags (Etiquetas)

Definición: Permiten agrupar y filtrar escenarios. Un QA experimentado usa Tags para organizar qué pruebas correr en el Pipeline (CI/CD) dependiendo del contexto.

Ejemplo de Aplicación: Correr solo las pruebas de sanidad en producción usando el comando de consola: cucumber --tags "@Smoke and not @WIP"

@Regresion @ModuloPagos
Feature: Pagos con Tarjeta

  @Smoke @PrioridadAlta
  Scenario: Pago exitoso con Visa
Hooks (@Before, @After)

Definición: Código técnico oculto que se ejecuta antes o después de los escenarios. A diferencia del Background (que es legible por negocio), los Hooks son puramente para el QA técnico (ej. limpiar cookies, abrir la base de datos, tomar captura de pantalla si falla).

// Ejemplo en JavaScript (Playwright/Cypress)
Before(async function () {
    // Iniciar navegador antes del escenario
});

After({tags: "@UI"}, async function (scenario) {
    if (scenario.result.status === Status.FAILED) {
        // Tomar captura de pantalla
    }
});

5. Step Definitions (El Código "Pegamento")

Definición: Es el código fuente (Java, JS, Python, C#) que mapea el texto de Gherkin a acciones reales (como usar Selenium). Cucumber usa Expresiones Regulares o "Cucumber Expressions" para capturar los parámetros de las frases.

// Ejemplo de Step Definition en JavaScript
Given('que el usuario navega a {string}', async function (url) {
  await browser.url(url);
});

When('hace clic en el botón {string}', async function (nombreBoton) {
  await page.click(`button:has-text("${nombreBoton}")`);
});
