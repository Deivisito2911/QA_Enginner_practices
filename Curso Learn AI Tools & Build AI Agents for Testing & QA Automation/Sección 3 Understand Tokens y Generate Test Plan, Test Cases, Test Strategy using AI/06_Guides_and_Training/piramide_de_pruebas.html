La Pirámide de Pruebas

Estrategia de Automatización en Ingeniería de Calidad (QA)

Pruebas Manuales (UX, Exploratorias)
UI / E2E (5 - 10%)
Integración / Servicios API (20 - 25%)
Pruebas Unitarias (70%+)

¿Qué es la Pirámide de Pruebas?

La Pirámide de Pruebas (Test Pyramid) es un modelo conceptual introducido por Mike Cohn. Sirve como guía para decidir qué nivel es el más adecuado para automatizar un caso de prueba, equilibrando velocidad de ejecución, costo de mantenimiento y confiabilidad. Nos indica la proporción ideal de pruebas que deberíamos tener en cada capa.

Los Niveles de Automatización

1. La Base: Pruebas Unitarias 70%+

¿Qué son? Prueban el código al nivel más bajo (funciones, métodos o clases individuales) de forma aislada mediante mocks y stubs.

  • Características: Extremadamente rápidas (milisegundos), baratas de mantener y localizan exactamente la línea donde ocurre el error.
  • ¿Qué automatizar?: Lógica de negocio, cálculos matemáticos, validaciones de datos y casos extremos (edge cases).

2. El Medio: Pruebas de Integración y API 20% - 25%

¿Qué son? Verifican que los diferentes módulos o servicios (bases de datos, APIs, microservicios) interactúen correctamente sin depender de la interfaz gráfica.

  • Características: Más lentas que las unitarias, pero mucho más rápidas y estables que las pruebas UI.
  • ¿Qué automatizar?: Respuestas de endpoints HTTP (200, 400, 500), integración con bases de datos, seguridad, y contratos de datos.

3. La Cima: Pruebas UI / End-to-End (E2E) 5% - 10%

¿Qué son? Simulan a un usuario real interactuando con la aplicación completa a través del navegador web o dispositivo móvil (ej. Selenium, Cypress, Playwright).

  • Características: Lentas de ejecutar, frágiles (propensas a falsos positivos por problemas de red o cambios de diseño) y costosas de mantener.
  • ¿Qué automatizar?: Solamente flujos críticos de negocio (Happy Paths). Ejemplos: login exitoso, flujo completo de pago o registro de usuario.

Más allá de la Automatización

Pruebas Manuales Exploratorias No Automatizable

La pirámide no elimina la prueba manual; la desplaza hacia tareas de mayor valor cognitivo donde la inteligencia humana es insustituible.

  • Pruebas Exploratorias: Donde el QA aplica su ingenio e intuición para descubrir comportamientos inesperados fuera de los scripts.
  • Usabilidad (UX): Evaluar si el sistema es intuitivo, estéticamente agradable y accesible para usuarios reales.
  • Funcionalidades Efímeras: Campañas de marketing cortas donde automatizar cuesta más de lo que ahorra.

🚨 El Anti-Patrón: El Cono de Helado (Ice Cream Cone)

Un error común en equipos que recién comienzan con la automatización es crear demasiadas pruebas de UI y casi ninguna prueba unitaria. Esto invierte la pirámide creando un "cono de helado".

Consecuencias: Pipielines de integración continua (CI/CD) que tardan horas en ejecutarse, pruebas que fallan por intermitencias (flakiness) y equipos frustrados por el alto costo de mantenimiento.
